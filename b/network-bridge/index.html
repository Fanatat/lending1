network-bridge

Локальный прокси-мост, который говорит на двух протоколах сразу.

Кадр-доказательство

Анимированная схема пути пакета: клиент → мост 0.0.0.0:1080 → ISP-прокси → дата-центр. Тумблер переключает протокол клиента SOCKS5 / HTTP — видно, как мост в случае HTTP превращает запрос в CONNECT-туннель. Сбоку — самотест 2/2: одиночный туннель до Telegram DC и восемь параллельных туннелей.

Цена решения

Почему документация построена лестницей «от простого к сложному» — сначала настройка прокси прямо в клиенте, только потом bridge.py, и лишь в крайнем случае Proxifier с готовым профилем. Потому что инструмент, который начинается с самого мощного решения, гарантированно будет применён неправильно.

Trade-off: документация длиннее и выглядит избыточной для опытного пользователя.
